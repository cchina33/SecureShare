# 実装計画書: 有効期限自由設定（最大30日）＆保持モード選択 (SecureShare)

## 1. 概要
共有シークレットの保存期間を最大30日までユーザーが自由に指定できるようにし、かつ「1回閲覧で即座破棄（ワンタイム）」か「有効期限まで何度でもアクセス可能（期限保持）」かを選択可能にします。

## 2. データベース設計変更 (`secrets`)
新カラム `burn_after_read` を追加：
- `1` (デフォルト): ワンタイム閲覧。閲覧と同時に物理削除。
- `0`: 期限保持。有効期限（`expires_at`）を迎えるまで何度でも復号閲覧可能。

```sql
ALTER TABLE secrets ADD COLUMN burn_after_read INTEGER DEFAULT 1;
```

## 3. API 仕様変更

### (1) `POST /api/secret`
- リクエストボディに `burn_after_read` (数値 `1` または `0`) を追加。
- `ttl_seconds`: 3600 (1時間) 〜 2592000 (30日) まで許容。

### (2) `GET /api/secret/:id`
- レコード取得後：
  - `expires_at < now` の場合は 404 を返却し物理削除。
  - 有効な場合：
    - `burn_after_read === 1` の場合のみ `DELETE FROM secrets WHERE id = ?` を実行。
    - `burn_after_read === 0` の場合は DELETE を実行しない。
- レスポンスに `burn_after_read` (1 or 0) および `expires_at` を含める。

## 4. UI/UX 設計

### 作成画面 (`index.html`)
- **消去モード選択**:
  - ラジオボタン/カードデザイン:
    - ⚡ **閲覧後にすぐ消去（ワンタイム）**: 最も安全。開くと自動破棄。
    - ⏳ **有効期限まで保持**: 期限内であれば同じリンクから再確認可能。
- **有効期限**:
  - 選択肢: 1時間、24時間、3日、7日、14日、30日、**「日数を直接指定（カスタム）」**
  - カスタム選択時: 「1〜30日」の数値入力フォームを表示。

### 閲覧画面 (`view.html`)
- `burn_after_read === 1`: 従来通り「注意：再閲覧はできません」「シークレットを表示して破棄する」
- `burn_after_read === 0`: 「このシークレットは◯月◯日まで有効です」「シークレットを表示する」
